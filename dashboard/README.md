# CAMINA Dashboard

Next.js 16 App Router dashboard for the CAMINA urban-mobility counter.
Follows `../plan/02-dashboard-vercel.md` and `../DESIGN.md`.

## Quick start (mock data, no database)

```bash
cd dashboard
pnpm install
cp .env.example .env.local
# Optional: edit .env.local — mock mode works out of the box.
pnpm dev
```

Open <http://localhost:3000> → redirects to `/dublin`.

The mock pill confirms you're in fixture mode. Fixtures live at
`../data/mock/dublin/` and are regenerated by:

```bash
cd ..
python scripts/generate_mock_dublin.py
```

## Modes

| `CAMINA_DATA_SOURCE` | Source | When to use |
|---|---|---|
| `mock` (default) | JSON fixtures in `../data/mock/<city>/` | Local dev, preview deploys, Playwright E2E |
| `live`           | Postgres (Neon + PostGIS) | Production |

The switch happens in `src/lib/data-source.ts` and is propagated by the
`streetsRepo` factory in `src/lib/repo/index.ts`.

## Architecture at a glance

```
Client (Next.js, MapLibre)
  ├── /[city]            public street map
  ├── /[city]/street/…   street detail (Recharts)
  └── /admin/…           protected admin console

Server (Next.js Route Handlers on Vercel Fluid Compute)
  ├── /api/streets*        public (no GPS, no sensor_id)
  ├── /api/metrics         public, keyed to basemap paint
  ├── /api/ingest/…        device-facing, Bearer auth
  └── /api/cron/…          scheduled via vercel.ts

Data
  ├── mock  → JSON fixtures, zero-DB dev
  └── live  → Neon Postgres + PostGIS (see drizzle/migrations/0000_init.sql)
```

## Privacy guarantees

- Public API bodies never contain `sensor_id`, `latitude`, or `longitude`.
- `tests/unit/privacy-regression.test.ts` enforces this in CI; add new public
  routes to that test before shipping.
- `DESIGN.md` + `plan/02-dashboard-vercel.md` §7 capture the full privacy
  model.

## Conventions

- Server Components by default. `'use client'` only where needed.
- Async `params` / `searchParams` (Next.js 15+).
- `proxy.ts` (not `middleware.ts`) for network-boundary concerns; auth
  lives in server-component layouts.
- Tailwind tokens from `tailwind.config.ts` match `DESIGN.md` §2–§6.
- Cache with `use cache` + `cacheTag()` + `revalidateTag()`.
